Presentación del producto

¿Qué es Gestión de Citas Inteligente?

🏥
¿Qué es?
Una plataforma web para facilitar la gestión de citas médicas de forma rápida, organizada y accesible. Permite registrarse, iniciar sesión, solicitar turnos, consultar citas e historial.
🎯
¿Para qué sirve?
Mejorar la experiencia del paciente y hacer más eficiente la administración de citas, evitando procesos manuales y pérdida de tiempo.
⚡
¿Qué puede hacer el usuario?
  • Registrarse e iniciar sesión de forma segura
  • Solicitar y consultar turnos médicos
  • Revisar historial de citas
  • Recibir información desde un solo lugar
📈
¿Por qué importa la arquitectura?
Al usar una arquitectura distribuida, el sistema está preparado para crecer e incorporar nuevos servicios de forma escalable y mantenible.
Una experiencia moderna, clara y confiable para la gestión de citas inteligentes.

Introducción

¿Qué problema se quería resolver?

⚠️
El problema inicial
Sin separación de ambientes, las pruebas, el desarrollo y la versión estable comparten la misma base de datos. Esto genera conflictos, pérdida de datos y errores difíciles de rastrear.
🎯
La solución planteada
Tres ambientes completamente independientes: develop para desarrollo activo, qa para pruebas y main para la versión estable. Cada uno con su propio stack.
🗄️
El riesgo de ddl-auto=update
Hibernate aplicaba cambios automáticos a la base de datos sin control. Al cambiar una entidad, la estructura podía romperse sin dejar historial ni rastro.
🔒
Lo que se necesitaba
Control explícito y versionado de la BD mediante migraciones con Liquibase, y configuración ordenada por perfiles de Spring Boot para cada ambiente.
Arquitectura técnica

Microservicios del sistema

🔀
api-gateway
Único punto de acceso. Centraliza el enrutamiento, la seguridad y el control de acceso hacia cada microservicio.
🐳
Docker Compose
Define y levanta todos los contenedores en un solo comando. Cada servicio con su red y volúmenes configurados.
👤
users-service
Autenticación JWT, registro de usuarios, perfil y roles. Base de datos propia por ambiente.
📅
turnos-service
Lógica completa de agendamiento. Integra Liquibase para versionar la estructura de la base de datos.

Cada microservicio es independiente: desplegable, escalable y con su propia base de datos.

Herramienta de Control de BD

¿Qué es Liquibase?

Liquibase es una herramienta de código abierto que permite versionar, controlar y aplicar cambios a la estructura de bases de datos de forma ordenada, reproducible y segura, a través de archivos de migración llamados changelogs.
❌
Antes: ddl-auto=update
Hibernate modificaba las tablas automáticamente al arrancar. No dejaba historial y era peligroso en ambientes con datos reales.
✅
Ahora: Liquibase
Cada cambio se define en un archivo versionado. Liquibase registra qué cambios ya aplicó. El historial es trazable, reversible y auditado.
📋
databasechangelog
Tabla interna que guarda el registro de cada migración: id, autor, fecha de ejecución y hash del cambio.
🔒
databasechangeloglock
Evita que dos instancias apliquen migraciones al mismo tiempo. Previene condiciones de carrera en la BD.
Organización de Archivos

Estructura de changelogs y configuración

📁 Árbol de directorios

📁 src/main/resources/ 📁 db/ 📁 changelog/ 📄 db.changelog-master.yaml 📁 changes/ 📄 001-create-turnos-table.yaml 📄 002-add-estado-column.yaml 📄 003-create-index.yaml

📌 El archivo db.changelog-master.yaml incluye todos los changelogs en orden. Liquibase los ejecuta secuencialmente y registra cada uno.

⚙️ Propiedades clave

application-develop.properties — turnos-service
# Hibernate no toca el esquema spring.jpa.hibernate.ddl-auto=none # Activar Liquibase spring.liquibase.enabled=true # Ruta al changelog maestro spring.liquibase.change-log=classpath:db/changelog/db.changelog-master.yaml # Base de datos del ambiente spring.datasource.url=jdbc:mysql://localhost:3306/turnosdb_develop

💡 Los mismos changelogs se aplican en cada base de datos. Todos los ambientes terminan con la misma estructura de tablas.

Posibles Preguntas del Profesor

Preguntas frecuentes y respuestas

❓ ¿Qué es un ambiente en este contexto?
Es un entorno de ejecución independiente con su propia configuración, puertos y base de datos. Permite que el mismo proyecto funcione en diferentes contextos sin interferencia.
❓ ¿Por qué no hacer tres proyectos diferentes?
Porque implicaría triplicar el código, aumentar el mantenimiento y perder coherencia. Con perfiles de Spring Boot, el mismo código se adapta a cada ambiente con solo cambiar la configuración.
❓ ¿Por qué cambiar los puertos entre ambientes?
Para poder ejecutar los tres ambientes al mismo tiempo en la misma máquina sin conflictos de red. Cada bloque de puertos identifica claramente a qué ambiente pertenece.
❓ ¿Qué ventaja tiene Liquibase sobre ddl-auto=update?
Liquibase aplica cambios de forma controlada y versionada. ddl-auto=update era automático, sin historial y potencialmente destructivo. Con Liquibase, cada cambio queda registrado en databasechangelog.
❓ ¿Para qué sirve el API Gateway?
Es el punto de entrada único. El cliente no necesita saber las IPs de cada microservicio. El gateway centraliza el enrutamiento, la seguridad y el control de acceso.
